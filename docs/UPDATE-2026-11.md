# Update proposal — November 2026

The app was built in June 2026, but its model choices were already a year old then:
Qwen3 (April 2025), Phi-4 (Dec 2024), `nomic-embed-text`, and Gemini 2.5. This doc
covers what has changed since, what it breaks, and what it makes possible. It is ordered
by urgency: **regressions first, then upgrades, then new capabilities.**

**Confidence key:** **H** = checked against a primary source (Ollama's docs/source,
Qwen's own README, PyPI metadata) or reproduced in this repo · **M** = one official
source quoted by secondaries, or several consistent secondaries · **L** = third-party
aggregator only, or the sources conflict. Benchmark numbers are vendor-reported unless
noted. The research container could reach PyPI and GitHub but not Hugging Face,
ollama.com or ai.google.dev, so model-card numbers come second-hand.

---

## 1. Regressions — fix now

### 1.1 Ollama cloud models slip past the local-only blocker — **fixed in this change** (H)

Ollama now names most cloud models `<model>:cloud` (`gemma4:cloud`, `kimi-k3:cloud`,
`glm-5.3:cloud`, `deepseek-v4-flash:cloud` all appear in its docs). The blocker matched
only `-cloud` and `cloud)`, so `gemma4:cloud` was treated as a local model. If you had
pulled one, you could select it as the main or fast model, and grading, People reviews
and capture would have been sent to ollama.com. That breaks the README's main promise.

Fix: `:cloud` is added to `CLOUD_MODEL_MARKERS`. `local_model_names()` also drops any
`/api/tags` entry that carries `remote_host` or `remote_model`, the structural fields
Ollama sets on cloud-proxied models (`docs/openapi.yaml`, `ModelSummary`). That check
holds even if the naming changes again. Tests are in `tests/test_local_only.py`.

Belt-and-braces, worth adding to the README: Ollama now has a global off switch,
`OLLAMA_NO_CLOUD=1` or `{"disable_ollama_cloud": true}` in `~/.ollama/server.json`
(Ollama FAQ, "How do I disable Ollama's cloud features?").

### 1.2 The cloud-assist default model is past its shutdown date (M)

Google's deprecations page lists `gemini-2.5-flash` with a shutdown date of
**2026-10-16** and names `gemini-3.5-flash` as the replacement. The forum reports
404s around that date. `CLOUD_DEFAULT_MODEL` and every entry in `CLOUD_MODELS` are 2.5-series, so
"Improve with Gemini" is probably failing now, or soon will.

Recommendation:
- Replace the hardcoded tuple with discovery: call `GET /v1beta/models` once per session
  and offer the `*flash*` models that support `generateContent`, with a pinned default as
  a fallback. That stops the list from going stale every ~12 months.
- Keep the default to a Flash-tier model that's on the free tier. Secondary sources list
  `gemini-3.8-flash`, `gemini-3.6-flash` and `gemini-3.5-flash-lite` as free-tier (L).
  Check against `ai.google.dev/gemini-api/docs/models` before pinning one.
- **Privacy disclosure the README doesn't make:** on the free tier, Google may use
  prompts to improve its products, and humans may review them (M, several secondaries
  quoting the Gemini API terms). The People/Private gates and name redaction still hold.
  But "free key" should say so in the Settings toggle text.

### 1.3 Ollama's default context is 4k on most GPUs; the app never sets `num_ctx` (H)

Ollama's `docs/context-length.mdx`: *< 24 GiB VRAM → 4k context; 24–48 GiB → 32k;
≥ 48 GiB → 256k.* `app/services/llm.py` never passes `num_ctx`. On a 12–16 GB card,
`generate_cards()` sends the system prompt (~400 tokens) plus the **uncapped** transcript,
leaves thinking on, and allows `num_predict=1800`. A medium Reflect session plus a
reasoning trace can exceed 4,096 tokens. When it does, Ollama shifts or truncates the
context and the system prompt is the first thing lost. The symptom looks like "the model
ignored the instructions" or truncated JSON, which the retry path then hides.

Recommendation: pass `options.num_ctx` on every call. Size it per call: 8k for
grading/classifying, 16k for card/rubric generation and chat. Cap `transcript` in
`generate_cards()` the way `extract_key_ideas()` already caps it at 4,000 characters.
Confidence that this truncates in practice: **M**. It depends on transcript length and
how long the model thinks. The 4k default itself is **H**.

### 1.4 Python 3.9 floor blocks current dependencies (H)

Python 3.9 reached end of life in October 2025. On PyPI today, `fsrs` 6.3.2 (2026-08-09)
and `fastapi` 0.162 (2026-10-23) both declare `requires_python >= 3.10`. On 3.9, pip
quietly installs years-old FastAPI, and §2.3 can't happen at all. Move the floor to
3.10 and test CI on `["3.10", "3.13"]`.

## 2. Upgrades

### 2.1 Refresh the local model ladder

What's new among open-weight models (release dates from Qwen's GitHub README, H):

| Family | Released | Sizes | Notes |
|---|---|---|---|
| **Qwen3.5** | Feb–Mar 2026 | 0.8B, 2B, 4B, 9B dense; 27B dense; 35B-A3B, 122B-A10B MoE | Apache-2.0 per card. Model card: GPQA-Diamond **81.7 (9B)**, **76.2 (4B)** (M, quoted from the HF card) |
| **Qwen3.6** | Apr 2026 | 27B dense, 35B-A3B MoE | coding-focused refresh |
| **Qwen3.8** | 2026-08-14 | 27B dense (plus a 2.4T-A95B flagship nobody runs locally) | GPQA-Diamond **89.2** (M, card via secondaries). `reasoning_effort` control |
| **Gemma 4** | 2026-04-02 | E2B, E4B, 26B MoE (~3.8B active), 31B dense | Apache-2.0 for the first time. Multimodal (images on all sizes; audio on E2B/E4B), 256K context. 26B: GPQA-Diamond **82.3**, AIME'26 **88.3**; E4B: **58.6 / 42.5** (M, card via secondaries) |
| **embeddinggemma** | 2025 | 300M, 768-d | now the example model throughout Ollama's own embeddings docs (H) |
| **qwen3-embedding** | 2025 | 0.6B, 4B, 8B | 0.6B ≈ 70.7 MTEB-eng-v2 (L, aggregator) |

Proposed ladder (replaces the README table and `web/js/models-info.js`):

| VRAM | Main | Fast (grading, filing) | Why |
|---|---|---|---|
| 24 GB+ | `qwen3.8:27b` · alt `gemma4:31b` | `gemma4:e4b` or `qwen3.5:4b` | the 27B dense Q4 is ~17–18 GB, leaving room for 16k context |
| 16 GB | `gemma4:26b` (MoE) | `qwen3.5:4b` | ~4B active parameters, so 30B-class knowledge at small-model speed. Survives partial CPU offload far better than a dense model |
| 12 GB | `qwen3.5:9b` | `qwen3.5:2b` | fits fully on GPU at Q4 with headroom |
| 8 GB | `qwen3.5:4b` or `gemma4:e4b` | `qwen3.5:0.8b`/`2b` | |
| Embeddings | `embeddinggemma` | — | Ollama's current reference model, small, multilingual |

Confidence: **H** that these families exist and are in Ollama (the base tags `gemma4`,
`gemma4:31b`, `gemma4:e2b`, `qwen3.5`, `qwen3.6`, `qwen3.8` and `embeddinggemma` appear
in Ollama's docs). **M** for the exact size tags (`:9b`, `:26b`, `:27b`). Confirm with
`ollama pull` before hardcoding. **M–L** for VRAM figures: rule of thumb ≈ 0.6 bytes per
parameter at Q4 plus KV cache.

`DEFAULT_MODEL` fallback: since `resolve_model()` already falls back to "same base
name", set `DEFAULT_MODEL = "qwen3.5:9b"`. It fits the median GPU, unlike `qwen3:14b`,
which is two generations old.

**Caveat on the benchmarks above.** GPQA and AIME measure solving hard problems. The
fast model's job is checking a learner's recall against an answer key, idea by idea,
which is a different skill. A 4B model with thinking turned off can trail on AIME and
still match a 27B on this. Pick using the eval in §2.2, not the leaderboard.

### 2.2 Choose models with your own data: a grading eval (recommended over any table)

The repo already has the test set: `seeds/` holds ~500 cards with key-idea rubrics. A
script such as `tools/eval_grader.py` would:
1. For each rubric, build synthetic recalls with a known answer per idea: full (all
   hit), paraphrased, one idea dropped, one idea subtly wrong, and blank. Write them
   once (by hand or with the main model), freeze them, and check them in.
2. Run `grade_rubric()` on each installed model with the app's real prompt and
   `think=False`.
3. Report per-idea agreement (hit/partial/miss), the false-"hit" rate (the costly
   error: it lets a forgotten idea through), and p50/p95 latency.

Later, add real labels: reviews where you overrode the suggested rating are cases the
AI got wrong. `reviews.ai_verdict` and `reviews.rating` are already stored.

This turns "which fast model?" into a two-minute measured answer on your own GPU. It
also catches prompt regressions when you upgrade models. It's the most durable item here.

### 2.3 Swap the hand-rolled FSRS for `py-fsrs` 6.x (H)

`IMPROVEMENTS.md` §1.1 already argued for this. `app/core/fsrs.py` is still an FSRS-4.5
port with 17 weights. `fsrs` 6.3.2 on PyPI implements FSRS-6 (21 parameters, short-term
memory modelled natively). It is MIT-licensed and its only runtime dependency is
`typing-extensions`. Once §1.4 lifts the Python floor, nothing blocks it.

Keep the optimizer **out of `requirements.txt`**: `fsrs[optimizer]` pulls in `torch`,
`numpy`, `pandas` and `tqdm` (PyPI `requires_dist`). Offer it as an optional
`tools/optimize_fsrs.py` that reads the `reviews` table and writes fitted parameters to
settings, gated on ~1,000 reviews.

Migration: map existing `(stability, difficulty, state, due)` into `fsrs.Card`. FSRS-6
reads 4.5-era S/D as-is with small drift. Replace `tests/test_fsrs.py` with tests that
pin the library's behaviour at your settings (retention 0.70–0.97).

### 2.4 Use Ollama's thinking-level discovery (H)

`/api/show` now returns `thinking: {values, default}`: booleans for on/off models,
strings like `low/medium/high` for leveled ones. Some models (gpt-oss) cannot turn
thinking fully off, so `think=false` is ignored and the token cap gets eaten. That is
the failure `_complete_json`'s retry chain works around. On model resolve, read
`/api/show` once and cache it. Then:
- grading/classifying: `false` if allowed, else the lowest level;
- card/rubric generation: the model default (or `medium`).

Ollama now returns reasoning in a separate `message.thinking` field, so `_ThinkFilter`
and `strip_think()` become a fallback for old servers only.

### 2.5 Store the embedding model name with each vector (H — gap in current code)

`embeddings.text_hash` hashes only the text. If you switch `EMBED_MODEL` (e.g. to
`embeddinggemma`), vectors of the same dimension from two different models get compared
as if they were one space. Related-concepts and duplicate warnings then quietly turn to
noise. Different dimensions just score 0 via `cosine()`. Add the model name to the
hash, or store it as a column, so a model change re-embeds automatically. Do this
*before* recommending a new embed model.

## 3. New capabilities the current models unlock

### 3.1 Check paper sketches from a photo (H that models support images; M on grading quality)

Gemma 4 takes image input at every size, and it is the example model in Ollama's
vision docs. Sketch tasks are currently self-checked against a feature checklist. With
a vision model, the learner snaps the paper sketch (phone or webcam), and the local
model checks each checklist feature (axes labelled? knee at the endurance limit?) with
the same ✓/◐/✕ UI as `grade_rubric`. Learning-science fit: the drawing effect stays the
learner's work, and the AI only gives feedback, as with text recall. People cards stay
excluded, as they already are from all grading.

Also enabled, lower priority:
- **Capture from a photo** of a textbook page or whiteboard → `split_topics()`.
- **Image-occlusion suggestions**: the vision model proposes the label regions to
  hide on an imported diagram (IMPROVEMENTS §2.3).

### 3.2 Spoken free recall, fully local (M — needs a spike)

Gemma 4 E2B/E4B accept audio, up to 30 s per clip, with speech recognition as a listed
task (Unsloth docs and model-card secondaries). Saying an answer aloud is faster than
typing, so more people would actually do effortful recall, which is the app's core
bet. Avoid the browser's Web Speech API: Chrome sends audio to Google, which breaks the
local-only guarantee. **Unverified:** whether Ollama's API accepts audio input today.
Its docs cover images and TTS (`phonon`) but don't mention audio input. If it doesn't,
`faster-whisper` (CPU-friendly) is the fallback. Spike before committing.

### 3.3 One OpenAI-compatible backend path (M)

Ollama, LM Studio, llama.cpp's `llama-server`, MLX servers on Macs, and most low-cost
hosted APIs all speak the OpenAI Chat Completions format. A single `base_url` + model
setting would let Mac users run MLX and would make cloud assist provider-agnostic.
Use it only for the per-click opt-in paths, with the same People/Private gate, the
redaction and the audit log.

Rough cost of the cloud assist on a paid tier, per card rewrite (~1.5k tokens in,
~0.6k out). **Prices are L: aggregator-reported, and they conflict:**
- DeepSeek V4.1 Flash, ~$0.30/$1.20 per M tokens at peak: ≈ **$0.001 per rewrite**
  (≈ $1 per 1,000).
- Gemini 3.6/3.8 Flash paid, ~$0.75/$3.75 intro pricing to 2026-12-31: ≈ **$0.003 per
  rewrite**.

At this app's usage (tens of rewrites a week), any of these costs cents a month. The
choice should rest on data handling, not price. Paid tiers generally don't train on
prompts, while the Gemini free tier may.

## 4. Suggested order

1. ✅ `:cloud` / `remote_host` blocker (this change) · add `OLLAMA_NO_CLOUD` to the README
2. Gemini model discovery + new default + free-tier disclosure (§1.2)
3. `num_ctx` per call + transcript cap (§1.3)
4. Python ≥ 3.10 (§1.4) → `py-fsrs` 6 (§2.3)
5. Grading eval harness (§2.2) → then update the model ladder from its results (§2.1)
6. Thinking discovery (§2.4) · embed-model-aware hashing (§2.5)
7. Photo sketch check (§3.1) · audio spike (§3.2) · OpenAI-compatible backend (§3.3)
